## 목표

챕터의 마지막 화면에서 넘기면, 다음 챕터 첫 화면이 같은 장 안에서 쪽을 넘길 때와 똑같이 **한 번의 300ms 미끄러짐**으로 이어서 들어온다. 이전 챕터로 갈 때도 마찬가지다. 그 사이에 빈 화면이 보이지 않는다.

## 배경

2026-11-25 Vercel 미리보기 화면 녹화(2장 마지막 쪽 → 3장 → 2장 → 3장)를 프레임 단위로 재 보니, 챕터를 넘길 때마다 본문이 **약 0.23초 동안 완전히 비었다** (1.23–1.47초, 2.52–2.72초, 3.30–3.52초). 챕터 하나를 넘기는 데 걸리는 시간도 쪽 넘김(300ms)의 약 두 배였다.

원인은 지금 구현이 챕터 경계를 두 번의 따로 된 움직임으로 처리하기 때문이다 (`use-reader.ts`의 `ChapterTransition`).

1. `leaving`: 지금 띠를 한 화면 더 밀어서 **빈 쪽**이 보이게 한다 (300ms `ease-in-out`). `transitionend`를 기다린다.
2. `entering`: URL을 다음 챕터로 바꾸고, 새 챕터 본문을 `slide-in-from-right`로 **화면 밖(100%)에서** 끌고 들어온다 (300ms `ease-in-out`).

두 움직임 모두 끝과 시작이 느려서, 1의 끝부분과 2의 앞부분에서 빈 화면만 보인다. Phase 07이 정한 동작은 "마지막 쪽에서 넘기면 다음 챕터 첫 쪽이 같은 방향으로 미끄러져 들어온다"였는데, 실제로는 "밀어내고 → 비고 → 들여온다"가 되었다.

2026-11-24 FE·BE 회의(Confluence "FE, BE API/마일스톤 회의")의 E4(책 목록과 챕터 본문)에서 "프론트에서 프리로드로 2챕터 정도 미리 가져오는 방식"을 채택했다. 이 phase는 경계에서 이웃 챕터 본문을 미리 그려야 하므로, 미리 받기를 이 결정에 맞춘다.

## 범위

### 하는 것

- 챕터의 첫 화면·마지막 화면에 있을 때, 이웃 챕터의 맞닿은 화면(다음 챕터는 첫 화면, 이전 챕터는 마지막 화면)을 지금 띠 바로 옆에 미리 그려 둔다. 지금 띠와 같은 움직임을 따라간다.
- 챕터 경계에서 넘기면 지금 띠와 이웃 화면이 함께 한 화면만큼 미끄러진다. 쪽 넘김과 같은 300ms `ease-in-out`이다. 미끄러짐이 끝나면(`transitionend`) URL과 챕터를 바꾸고, 새 챕터는 **애니메이션 없이 같은 자리에** 그린다.
- `entering` 단계와 `slide-in-from-*` 애니메이션을 없앤다.
- 끌어 넘기는 도중 챕터 경계를 넘으면, 빈 쪽 대신 이웃 챕터의 화면이 손가락을 따라온다.
- 미리 받기: 지금 챕터 앞뒤로 2챕터까지 받아 둔다 (회의 E4 결정). 지금은 경계 두 화면 전부터 이웃 1챕터만 받는다.

### 하지 않는 것

- 목차에서 챕터로 바로 가기: 지금처럼 애니메이션 없이 바로 바뀐다.
- `prefers-reduced-motion`: 지금처럼 미끄러짐 없이 바로 바뀐다.
- 쪽 계산(`paginate.ts`), 쪽 크기(`geometry.ts`), URL 규칙(`?chapter&s`), 키보드·탭·끌기 판정(`swipe.ts`)은 바꾸지 않는다.
- 이웃 챕터 본문을 아직 받지 못했을 때의 동작은 바꾸지 않는다 (지금처럼 빈 쪽으로 넘어가고, 도착하면 스켈레톤 → 본문). 미리 받기를 넓혀서 이 경우를 줄인다.
- 3D로 넘어가는 효과나 다른 넘김 방식 (07의 "하지 않는 것" 그대로).

## 설계

### FSD 배치

| 레이어 | 슬라이스      | 세그먼트 | 만들거나 바꿀 것                                                                                                                              |
| ------ | ------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| pages  | `book-reader` | model    | `use-reader.ts`: `entering` 제거, 이웃 챕터 조회와 이웃 화면 위치 계산, 2챕터 미리 받기. `use-pagination.ts`: 재는 ref와 움직이는 띠 ref 분리 |
| pages  | `book-reader` | ui       | `PageStage.tsx`: 움직이는 틀(지금 띠 + 이웃 화면)로 나누고 들어오는 애니메이션 제거. 이웃 화면 컴포넌트 추가                                  |

다른 레이어는 바꾸지 않는다.

### 구조

```
보이는 영역 (overflow: clip, 너비 = 한 화면)
└─ 움직이는 틀 (transform = -offset + 끌린 거리, 300ms 미끄러짐)   ← use-swipe와 transitionend가 여기 붙는다
   ├─ 이전 챕터 마지막 화면  (left = -한 화면 간격)        첫 화면에 있을 때만
   ├─ 지금 챕터 띠           (CSS 다단, 쪽 표를 재는 대상)
   └─ 다음 챕터 첫 화면      (left = 화면 수 × 한 화면 간격)  마지막 화면에 있을 때만
```

- "한 화면 간격" = 화면당 쪽 수 × (쪽 너비 + 간격). 지금 `viewStride`와 같다.
- 이전 챕터 마지막 화면은 그 챕터의 띠를 같은 크기로 그리고, 쪽 수를 재서 마지막 화면만큼 안에서 옮긴 뒤 한 화면 너비로 자른다. 쪽 수는 지금 챕터와 같은 `measurePages`로 잰다. 그래야 도착한 뒤 그려지는 마지막 화면과 같다.
- 지금의 `leaving`은 그대로 쓴다. 틀이 한 화면 더 가면 그 자리에 이웃 화면이 있다. 도착(`transitionend`) 뒤 새 챕터의 틀은 처음부터 다시 만들어진다(`key`). 그래서 미끄러짐 없이 새 위치에 놓이고, 쪽 표는 ref 콜백에서 화면을 그리기 전에 잰다.
- 이웃 화면은 보조 기술과 키보드에서 숨긴다 (`aria-hidden`, `inert`).

### API

바뀌는 것 없음. 이웃 챕터 본문은 지금과 같은 `chapterQuery`(`GET /api/books/{book_id}/chapters/{chapter_no}`, 지금은 MSW 목)로 받는다.

### 화면과 상태

- 이웃 챕터 본문이 있음: 경계에서도 쪽 넘김과 같이 넘어간다.
- 이웃 챕터 본문을 받는 중이거나 에러: 이웃 화면을 그리지 않는다. 넘기면 지금처럼 빈 쪽으로 나간 뒤 새 챕터의 스켈레톤이나 에러가 보인다.
- 지금 챕터의 로딩·에러 화면은 바꾸지 않는다.
