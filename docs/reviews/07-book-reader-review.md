### 1.4 이번 변경에서 특히 볼 것

- **ref 콜백 측정**: `use-pagination`은 키가 바뀌면 새 콜백을 만들어 커밋 직후 잰다. 키에 들어가지 않는 변화(본문 데이터가 같은 키로 다시 들어옴, 글꼴 로딩 뒤 줄바꿈이 바뀌었는데 `fontsReady`가 이미 `true`)에서 쪽 표가 낡지 않는지. React 19 Strict Mode에서 ref 콜백이 두 번 불려도 문제없는지, 정리 함수를 돌려주는지.
- **`transitionend`에 기대는 상태**: 챕터 경계의 `leaving` → 챕터 전환은 `transitionend`가 와야 끝난다. 전환이 시작되지 않는 경우(같은 `transform` 값, 탭이 백그라운드라 전환이 건너뛰어짐, 경계 중에 창 크기 변경, 자식 요소의 `transitionend` 버블링)에 `leaving`에 갇히지 않는지. reduced motion이 슬라이드 도중 바뀌면 어떻게 되는지.
- **연타와 겹친 입력**: 슬라이드 중 다시 넘기기, 드래그 중 키보드, 경계 `leaving` 중 목차 이동이나 뒤로 가기. `turn`이 진행 중 상태를 무시하거나 올바르게 이어 가는지.
- **`data-settling`과 인라인 스타일 정리**: 놓은 뒤 전환이 없는 경우(거리 0, `pointercancel`)에도 `--drag-dx`·`transition: none`이 지워지는지. 지워지지 않으면 다음 넘김이 미끄러지지 않는다.
- **드래그 판정**: 가로 10px·세로보다 많이 움직임 기준, `setPointerCapture` 뒤 버튼·링크 클릭이 막히지 않는지(하단 막대는 무대 밖이지만 무대 위에 다른 컨트롤이 없는지), 마우스 오른쪽 버튼·멀티 터치를 무시하는지, 드래그 끝에 `click`이 탭으로 다시 처리되지 않는지.
- **`touch-action` 계획과 다름**: 계획은 `pan-y pinch-zoom`, 구현은 `touch-pan-y`. `pan-y`만 있으면 핀치 확대가 막혀 WCAG 1.4.4(텍스트 크기 조정)에 걸릴 수 있다.
- **iOS 가장자리 뒤로 가기**: 화면 왼쪽 끝에서 오른쪽으로 끄는 제스처와 "이전 페이지" 드래그가 겹친다. 기기가 없어 코드로만 판단할 수 있다면 가장자리 몇 px를 드래그 시작에서 뺄지 결정한다.
- **`100dvh`와 모바일 주소창**: 주소창이 접히고 펴질 때마다 높이가 바뀌어 다시 나뉜다. 다시 나뉠 때 미끄러짐 없이 같은 문장으로 돌아오는지(크기 변경은 `animate`가 꺼져야 함), 깜빡임이 있는지 높이를 몇 번 바꿔 확인.
- **`overflow: clip`과 찾기**: 화면 밖 쪽의 글은 Ctrl+F로 찾아져도 보이지 않는다. 찾기가 띠를 스크롤하지 못하는 대신 찾은 글이 안 보이는 한계를 기록한다. 바깥 무대가 `overflow-hidden`이라 무대 쪽이 스크롤될 여지는 없는지.
- **보이는 범위 경계**: 다단의 단 위치를 `floor((left + 1) / stride)`로 쪽을 정한다. 소수점 너비, 브라우저 확대, `devicePixelRatio`가 다를 때 한 쪽씩 밀리지 않는지. 쪽을 걸치는 문장이 두 쪽 범위에 모두 들어가는지, 빈 쪽(홀수 챕터 마지막 오른쪽)이 범위를 깨지 않는지.
- **`data-*` 범위 속성을 항상 노출**: 개발 전용이 아니라 배포에도 나간다. 계산 전(`layout` 없음)에 낡은 값이나 빈 값이 나가는지, 음악 phase가 이 값을 믿어도 되는지.
- **`last_position` 이어 읽기와 URL**: `?chapter` 없이 들어오면 `last_position`의 쪽으로 열리고, 첫 넘김 전에는 URL에 `s`가 없다. 이때 새로고침하면 서버 값에 기대는지, 챕터 링크만 있는 URL(`?chapter=2`)은 `last_position`을 무시하는지.
- **미리 받기 시점**: 다음 챕터는 마지막 2쪽(펼침)에 이를 때, 이전 챕터는 1쪽 이하에서 `prefetchQuery`. 목차로 바로 이동하거나 URL로 마지막 쪽에 들어왔을 때는 넘김이 없어 미리 받지 않는데, 그때 경계 넘김이 기다리는지(로딩 중 띠가 빈 화면으로 미끄러지는지).
- **창 keydown과 목차 판정**: 목차가 열렸는지를 `document.querySelector('[data-reader-toc][data-state="open"]')`로 본다. 다른 Radix 대화상자(앞으로 생길 것)가 열렸을 때도 키가 먹는 문제가 있는지. `Space`로 화면이 스크롤되지 않는지(`preventDefault`), IME 조합 중(`isComposing`) 키를 무시하는지.
- **`overlay` 토큰과 PR #17 충돌**: 열려 있는 PR #17(`design/15-focus-ring-contrast`, phase 08)도 `src/app/styles/index.css`와 `docs/design-system.md`를 고친다. 머지 순서에 따라 충돌이 나는 줄이 있는지 `git merge-tree`로 미리 본다. 08이 바꾸는 `--ring`과 이번 `sheet` 닫기 버튼·하단 막대 버튼의 포커스 링이 어떻게 맞물리는지.
- **`sheet` 고친 부분**: shadcn 원본과 비교해 접근성 속성(`SheetTitle`, `SheetDescription` 또는 `aria-describedby={undefined}`)이 빠져 Radix 경고가 콘솔에 나오지 않는지. 서랍 폭이 375px 화면에서 넘치지 않는지.
- **라우트 이동의 부작용**: 리더가 `RootLayout` 밖으로 나가 `ScrollRestoration`이 없다. 리더 → 목록 → 뒤로 가기에서 목록 스크롤 복원이 여전히 되는지. 리더 안의 404·에러 경계(`RouteErrorPage`)가 리더 레이아웃 없이도 돌아갈 길을 주는지.
- **문서와 코드 이름**: phase가 말한 `paginate`·`spreadOf`가 다른 이름으로 구현되었다. architecture.md와 phase 문서가 실제 이름과 맞는지.
- **작업 절차**: 05 브랜치의 `scripts/check-process.mjs`로 PR 설명까지 넣어 검사(`--body-file`). PR 설명에 `Closes #14`, phase·리뷰 문서 링크.

#### 1.4 결과

- **ref 콜백 측정**: 코드로 확인. 키가 바뀌면 새 콜백이 커밋 직후 재고, 본문은 `staleTime: Infinity`라 같은 키로 다른 데이터가 들어오지 않음. 콜백은 정리 함수를 돌려주지 않아 떼어질 때 `null`로 다시 불리고, 이때는 재지 않음. Strict Mode에서 두 번 재도 결과가 같아 문제없음. 글꼴은 챕터를 옮길 때마다 새 조각(unicode-range)을 받는 것을 확인(`loadingdone` 4–6개). `useFontsReady`가 `loading`을 듣지 않아 다른 렌더가 없으면 낡은 표가 남을 수 있었음 (발견 8). 실제로는 다른 상태 변화가 끼어 매번 맞게 나와 재현은 못 함.
- **`transitionend`에 기대는 상태**: 슬라이드 중 URL이 바뀌면 띠가 바뀌어 `transitionend`가 오지 않고 leaving에 갇힘 (발견 1). 백그라운드 탭에서는 전환이 늦게 끝날 뿐 이벤트는 옴. 크기 변경은 띠가 그대로라 전환이 이어짐.
- **연타와 겹친 입력**: 경계에서 3번 연타 → 한 챕터만. 같은 챕터 안 연타는 전환이 새 목표로 이어짐. 끌기 중에는 `transition: none`이라 leaving 전환이 끊기지만 놓을 때 다시 미끄러져 `transitionend`가 옴 (코드로 확인).
- **`data-settling`과 인라인 스타일 정리**: 제자리에서 놓으면 남음 (발견 6). 남은 상태에서 뒤로 가기로 위치가 바뀌자 띠가 미끄러짐(`getAnimations()`에 `transform`). `pointercancel`은 정리됨.
- **드래그 판정**: 무대 위에 다른 컨트롤 없음(본문 안 포커스 요소 0). 마우스 오른쪽 버튼 무시. 탭은 `pointerup`에서만 처리하고 `click` 처리기가 없어 두 번 처리되지 않음. 멀티 터치는 발견 3.
- **`touch-action`**: 발견 4.
- **iOS 가장자리 뒤로 가기**: 기기가 없어 확인 못 함 (3절). 리더는 `setPointerCapture`를 끌기가 시작된 뒤(10px)에야 하므로 시스템 제스처가 먼저 가져갈 것으로 보이지만, 가장자리 제외는 실제 기기에서 문제가 보이면 넣는다.
- **`100dvh`와 모바일 주소창**: 높이 변화는 창 크기 변경과 같은 경로(`useElementSize` → 키 변경 → 다시 잼)이고, 크기 변경 때 미끄러지지 않고 같은 문장으로 돌아오는 것을 1.2 #4에서 확인. 실제 주소창 동작은 확인 못 함 (3절).
- **`overflow: clip`과 찾기**: 찾기가 띠를 스크롤하지 못함(1.2 #12). 대신 화면 밖 쪽의 글은 찾아도 보이지 않음 (발견 11, 계획에서 받아들인 한계). 바깥 무대는 `overflow-hidden`이지만 내용이 무대보다 크지 않아 `scrollLeft` 0.
- **보이는 범위 경계**: 1.2 #10에서 소수점 너비가 나오는 크기(1023×768 등) 포함 모두 일치. 쪽을 걸치는 문장은 두 쪽 범위에 모두 들어감. 빈 쪽은 앞 쪽 마지막 문장으로 채워져 범위가 깨지지 않음. 브라우저 확대·다른 `devicePixelRatio`는 확인 못 함.
- **`data-*` 범위 속성을 항상 노출**: 쪽 표가 없을 때는 `data-first-sentence`·`data-last-sentence`가 빠지고(`range`가 null), 낡은 값은 나가지 않음. 음악 phase가 그대로 써도 된다.
- **`last_position` 이어 읽기와 URL**: `?chapter` 없이 열면 `last_position`(「봄·봄」 2장 89)이 든 펼침이 열리고 URL은 그대로. `?chapter=2`처럼 챕터만 있으면 `last_position`을 무시하고 첫 쪽(코드와 `?chapter=2&s=abc` 결과로 확인). `?s=100`만 있으면 `last_position` 챕터에서 `s`를 씀.
- **미리 받기 시점**: 마지막 2쪽 전에 다음 챕터 요청이 나감(1.2 #8). URL로 마지막 쪽에 바로 들어오면 미리 받지 않지만, 경계를 넘는 순간 요청하고 슬라이드(300ms) 동안 받음. 목 지연(400ms)이 더 길어 들어올 때 잠깐 스켈레톤이 보일 수 있음. 그대로 둠.
- **창 keydown과 목차 판정**: 목차가 열린 동안 화살표 무시(구현 기록), Space는 `preventDefault`로 화면 스크롤 없음. 앞으로 다른 대화상자가 생기면 `[data-reader-toc]` 대신 열린 대화상자 전체를 보도록 바꿔야 함. IME 조합 중(`isComposing`)은 입력창이 없어 해당 없음.
- **`overlay` 토큰과 PR #17 충돌**: `git merge-tree`로 `src/app/styles/index.css`에서 충돌 확인 (`--ring` 바로 아래에 이번 `--overlay`를 넣어서). 또 PR #17은 전역 `:focus-visible`을 2px outline으로 바꾸는데, 리더는 `outline-none focus-visible:ring-[3px]`를 써서 08 기준(design-system 4.6)과 달라짐 (발견 9).
- **`sheet` 고친 부분**: `SheetTitle`·`SheetDescription` 있음, 콘솔 경고 0. 375px에서 서랍 폭 281px.
- **라우트 이동의 부작용**: 리더 안 에러 화면은 "책 목록으로" 링크가 있음. 목록 스크롤 복원은 목 데이터가 3권뿐이라 목록이 스크롤되지 않아 확인 못 함 (3절).
- **문서와 코드 이름**: phase의 `paginate`·`spreadOf`는 `buildPageLayout`·`visibleRange`로 구현됨. architecture.md는 실제 이름을 씀. phase 문서는 계획 당시 이름이라 그대로 두고 이 문서에 기록.
- **작업 절차**: 05 브랜치의 `check-process.mjs`로 1~4번 통과. PR 설명(5번)은 PR을 만들 때 `--body-file`로 확인.

## 3. 확인 못 한 것

- **실제 터치 기기**: 끌기·탭·핀치는 합성 `PointerEvent`로만 확인. iOS 가장자리 뒤로 가기 제스처와의 충돌, 모바일 주소창에 따른 `100dvh` 변화는 확인 못 함.
- **Chromium 밖 브라우저**: 내장 브라우저(Chromium)로만 봤다. Safari의 다단 `getClientRects()` 차이(phase 위험 항목), Firefox, 스크린 리더 낭독은 확인 못 함.
- **OS의 움직임 줄이기 설정**: `matchMedia`를 덮어써 JS 쪽(챕터 경계 즉시 전환)만 확인. CSS `motion-safe:`가 실제로 전환을 끄는지는 설정을 바꿀 수 없어 확인 못 함.
- **브라우저 확대 200%, 다른 `devicePixelRatio`**: 확인 못 함.
- **목록 스크롤 복원**: 목 책이 3권이라 목록이 스크롤되지 않아 리더 → 목록 → 뒤로 가기의 복원을 볼 수 없음.
- **글꼴 조각 로딩 뒤 낡은 쪽 표(발견 8)**: 재현하지 못해 고친 코드가 그 상황을 막는지는 코드로만 확인.

## 4. 결론

수정 후 통과. 완료 기준 13개를 모두 확인했고, 발견 11건 중 8건을 `b6bb558`에서, PR #17 머지 뒤 충돌과 포커스 기준(발견 9)을 `614a183`·`cdf0fcf`에서 고쳤다. 가장 큰 것은 챕터 경계 슬라이드 중 뒤로 가기로 리더가 멈추던 문제(발견 1)와, 쪽을 걸치는 문장으로 시작하는 쪽을 다시 열 때 한 쪽 앞이 열리던 문제(발견 2)다. 남은 것은 받아들인 한계 두 가지다. 실제 터치 기기와 Safari 확인은 남아 있다.
