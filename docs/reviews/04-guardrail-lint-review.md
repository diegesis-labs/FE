### 1.4 이번 변경에서 특히 볼 것

각 항목 끝의 **→** 뒤가 결과다.

- **규칙의 빈틈**: 정규식과 선택자가 놓치는 경우를 찾아 사례로 시험한다. 막아야 하는데 안 막히면 고칠지, 대응표에 "일부"로 적을지 판단한다.
  - 인라인 스타일의 색 값: `style={{ color: '#333' }}` (hex 정규식은 `[#…` 임의값만 본다)
  - 임의값의 다른 형태: `bg-[rgb(0,0,0)]`, `bg-[var(--color-pine-700)]`, `bg-(--color-pine-700)`
  - 동적으로 조립한 클래스: `` `bg-${tone}-700` ``
  - Effect 우회: `import * as R from 'react'` 후 `R.useEffect`, `import { useEffect as ue }`
  - 타이머 우회: `const t = window; t.setTimeout(...)`
  - **→** 잡힘: `bg-[var(--color-pine-700)]`, `bg-(--color-pine-700)`, `cn('text-[#fff]')`, `import { useEffect as ue }`, `import * as R`(네임스페이스 import 자체가 막힘). 놓침: 인라인 style의 `#333`, `bg-[rgb(…)]`, `oklch(…)` → **고침** (발견 1). 동적 클래스와 변수에 담은 타이머는 **그대로 둠**: 동적 클래스는 Tailwind도 만들지 않아 어차피 동작하지 않고, 타이머 우회는 의도적인 회피라 리뷰로 본다. 둘 다 대응표에 "못 잡는다"로 적음
- **shadcn과의 충돌**: shadcn 기본 컴포넌트(예: `dialog`, `sheet`)는 `bg-black/50` 같은 기본 색을 쓴다. 기본 팔레트를 껐으니 그대로 추가하면 오버레이 색이 사라진다. `pnpm exec shadcn add dialog`로 실제로 무엇이 생기는지, lint가 잡는지 확인하고 지운다. `design-system.md`의 "추가한 뒤 고친다" 절차로 충분한지 판단한다. **→** `dialog.tsx`가 `src/shared/ui/`에 생기고 `bg-black/50`(40줄)에서 lint 에러 2개. 기본 색을 그대로 들여오는 것은 막힌다. 다만 오버레이에 쓸 의미 토큰이 아직 없어서, 실제로 dialog를 추가하는 phase에서 토큰부터 정해야 한다 (발견 4)
- **덮어쓰기 함정이 다시 생길 여지**: 제품 레이어 블록이 공통 상수를 다시 합쳐 넣는 구조다. 새 규칙을 공통 블록에만 넣고 제품 블록에 빠뜨리면 제품 레이어에서만 꺼진다. 자체 검사 사례가 제품 레이어 경로로도 공통 규칙을 시험하는지 확인한다. **→ 통과.** 공통 규칙(팔레트, 기본 색, hex, `fetch`, HTTP 라이브러리)을 모두 `pages`·`entities` 같은 제품 레이어 경로로도 시험한다. 구현 때 색 규칙을 제품 블록에서 빼 보는 시험으로 6개 사례가 실패하는 것도 확인됨
- **`noInlineConfig` 경고**: 제품 레이어에 disable 주석을 쓰면 경고가 난다. `pnpm lint`는 경고로 실패하지 않으므로, 주석 자체는 남을 수 있다. CI에서 `--max-warnings 0`이 필요한지 판단한다 (phase "위험 5"). **→ 그대로 둠.** 주석이 무시되어 원래 위반이 에러로 남으므로 규칙 우회는 불가능하다. 남는 것은 쓸모없는 주석과 경고뿐이라 지금은 CI를 더 엄하게 하지 않는다
- **`scripts/` lint 범위**: ESLint 설정이 `**/*.{ts,tsx}`만 보므로 `scripts/check-guardrails.mjs`는 lint되지 않는다. 문제가 되는지 본다. **→ 그대로 둠.** 스크립트는 Prettier가 포맷하고 `pnpm lint`가 매번 실행하므로 문법 오류는 바로 드러난다. ESLint 범위를 `.mjs`로 넓히면 설정 파일까지 브라우저 globals로 검사하게 되어 이번 범위 밖 (발견 5, 낮음)
- **Tailwind의 `docs/` 스캔**: `docs/guardrails.md`, `design-system.md`의 예시 문구(`bg-pine-700` 등)로 CSS가 생기는지, 크기 영향이 있는지 본다 (phase "위험 2"). **→** `bg-pine-700`, `text-wood-600`, `bg-cream-100`이 문서 예시 때문에 CSS에 생김. 크기 영향은 미미하지만 문서 문구가 CSS를 바꾸는 구조라 다음에 정리 (발견 6, 낮음)
- **`self` 전역 금지의 부작용**: `self`는 Web Worker에서 쓰인다. 아직 Worker가 없지만, 규칙이 `self.fetch`만 막는지(전역 `self` 사용 자체는 허용) 확인한다. **→ 통과.** `self.location.href`는 걸리지 않음
