### 1.4 이번 변경에서 특히 볼 것

- **이웃 본문을 받지 못했을 때:** `entering`을 없앴으므로, 이웃 챕터가 아직 없을 때 넘기면 빈 쪽으로 나간 뒤 새 챕터가 미끄러짐 없이 나타난다. 전에는 들어오는 애니메이션이 있었다. 목 지연(`LATENCY_MS`)을 두고 캐시가 빈 상태로 바로 경계를 넘겨 본다.
- **끌기 대상이 바뀜:** `use-swipe`가 이제 띠가 아니라 틀에 `--drag-dx`, `data-settling`, 인라인 `transition`을 쓴다. 놓은 뒤 `transitionend`가 틀에서 오고, 쪽 표를 재는 띠에는 transform이 없다. 끌다 놓았을 때 `settling`이 남지 않는지 본다.
- **쪽 표를 잴 때의 기준점:** `measurePages`는 띠의 `getBoundingClientRect().left`를 기준으로 잰다. 부모(틀)에 transform이 있어도 차이만 쓰므로 영향이 없어야 한다. 끄는 도중·미끄러지는 도중 크기가 바뀌어 다시 잴 때를 본다.
- **같은 문장 번호가 문서에 두 번 있음:** 이웃 화면에도 `data-sentence-idx` span이 있다. 문서 전체에서 이 속성을 찾는 코드가 없는지 확인한다 (`paginate.ts`는 띠 안에서만 찾음).
- **경계 화면이 한 화면뿐인 챕터:** 첫 화면이자 마지막 화면이면 이웃 화면이 양쪽에 다 그려진다. 위치가 겹치지 않는지.
- **`inert` 요소와 포인터:** 이웃 화면은 `inert`라서 포인터 이벤트의 대상이 되지 않는다. 이웃 화면이 보이는 상태(끄는 중)에서 끌기가 이어지는지.
- **미리 받기가 늘어난 만큼의 요청:** 전에는 경계 두 화면 전부터 1챕터, 이제는 열자마자 앞뒤 2챕터. 목에서는 문제없고, 실제 BE 연결 때 요청 수가 회의 결정(2챕터)과 맞는지.

## 3. 확인 못 한 것

- 이웃 챕터 본문이 도착하기 전에 경계를 넘기는 경우(발견 사항 1). MSW 서비스 워커가 응답해서 Playwright `route`로 특정 챕터만 늦출 수 없었고, 목의 지연은 모든 요청이 같다.
- 실제 터치 기기의 끌기, Safari·Firefox. Chromium(Playwright)과 마우스로만 확인했다.
- Vercel 미리보기 배포에서의 동작. 로컬 개발 서버(목)에서만 확인했다.
- 실제 BE 본문(E3 책 묶음)처럼 긴 챕터에서 이웃 화면을 한 번 더 그리는 비용.

## 4. 결론

통과. 챕터 경계가 쪽 넘김과 같은 한 번의 미끄러짐(약 300ms)으로 넘어가고 빈 화면이 없다. 발견 사항 셋은 모두 낮음이고 코드는 고치지 않았다. 남은 일은 E4 BE 연결 때 느린 네트워크에서의 경계 넘김과 미리 받기 요청 수를 다시 보는 것이다.
