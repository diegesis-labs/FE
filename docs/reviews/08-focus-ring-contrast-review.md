### 1.4 이번 변경에서 특히 볼 것

- **06과 합칠 때**: `feat/13-book-list`를 이 브랜치에 시험 머지(별도 worktree, 푸시 안 함)해서 충돌이 나는지, 06의 `BookCard`·`BookReaderPage`가 새 토큰으로 어떤 포커스 표시를 받는지(3px box-shadow 링 + `outline-none`이라 전역 outline과 겹치지 않는지). 06 머지 후 할 정리를 PR에 적는다. **→** 충돌 없음(`origin/feat/13-book-list` 당시 끝을 `--no-commit`으로 머지 후 취소). 06의 카드·"책 목록"·챕터 링크는 `outline-none` + 3px box-shadow 링이라 전역 outline과 겹치지 않고, 색만 새 토큰을 받음: 라이트 카드 `rgb(102,102,102) 0 0 0 3px`, 다크 "책 목록" `rgb(185,194,184) 0 0 0 3px`. 바탕과 3:1 이상이지만 표시 방식이 둘로 갈림 (발견 1)
- **전역 `:focus-visible`의 범위**: `@layer base`라 `outline-none` 같은 유틸리티가 이기는지. `tabindex="-1"`로 코드에서 포커스를 옮기는 요소(지금은 없음)에도 outline이 생길 수 있는지. **→** 버튼의 `outline-none`을 뺀 뒤 06의 `outline-none`이 전역 outline을 이김(위 확인). `src`에 `tabIndex`·`.focus()` 0건이라 지금은 해당 없음. 나중에 라우트 이동 때 제목에 포커스를 옮기면 그 요소에 `outline-none`이 필요한지 그때 판단
- **잘림**: 헤더와 레이아웃에 `overflow-hidden`이 있어 바깥으로 띄운 outline이 잘리는 곳이 있는지 (`RootLayout`, `Header`). **→** `src`에 `overflow` 0건. 06 머지 상태에서도 0건
- **모양**: 원형·아이콘 버튼(테마 버튼)에서 outline이 모서리를 따라 자연스러운지. **→** 테마 버튼은 각진 아이콘 버튼(`size-10`)이라 사각 outline. 확대 화면에서 어색하지 않음
- **shadcn 기본 CSS와의 충돌**: `shadcn/tailwind.css`가 `--ring`이나 `outline`을 따로 쓰는지. **→** `shadcn@4.23.0/dist/tailwind.css`에 `ring`·`outline`·`focus` 0건
- **빌드 CSS**: Tailwind가 `docs/`의 글에서 `focus-visible:ring-[3px]` 같은 클래스 이름을 읽어 쓰이지 않는 규칙을 만드는지. `main` 빌드와 비교해 이번 변경으로 새로 생긴 것인지. **→** 생김: `.focus-visible\:ring`, `.focus-visible\:ring-[3px]`, `.focus-visible\:ring-ring` 규칙이 phase 문서 글에서 만들어짐. `src`에 없는 `bg-wood-600`도 빌드 CSS에 있어 `docs/` 스캔은 원래 있던 동작 (발견 2)
- **고대비 모드(forced-colors)**: outline이 남는지 볼 수 있으면 본다. **→** 확인 못 함 (3절)
- **문서 일관성**: `line-strong`을 지운 뒤 레포에 남은 참조가 없는지 (`docs/reviews/`의 과거 기록은 제외). **→** `docs/reviews`·`docs/phases` 밖 0건

## 3. 확인 못 한 것

- **고대비 모드(forced-colors)**: 내장 브라우저에서 `forced-colors`를 흉내 낼 방법이 없어 보지 못했다. outline이 forced-colors에서 남는 것은 CSS 명세 동작이고, 지운 box-shadow는 원래 사라지는 쪽이었다.
- **PR CI**: 리뷰 결과를 쓰는 시점에는 PR을 아직 올리지 않았다. PR에서 확인한다.
