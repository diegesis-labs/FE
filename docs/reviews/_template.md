## 1. 리뷰 계획

리뷰를 시작하기 전에 이 절을 먼저 채운다. phase 문서를 다시 읽고 실제 변경(`git diff <계획 커밋>..<구현 커밋>`)을 본 뒤 작성한다. 이 절까지 쓰면 결과 칸은 비워 둔 채 커밋·푸시하고 나서 리뷰를 시작한다.

### 1.1 변경 요약

실제로 바뀐 파일과 내용을 짧게 적는다. phase 계획과 다른 점이 있으면 표시한다.

### 1.2 완료 기준 확인 방법

phase 문서의 완료 기준을 그대로 옮기고, 각각을 어떻게 확인할지 적는다.

| #   | 완료 기준                                        | 확인 방법 | 결과 |
| --- | ------------------------------------------------ | --------- | ---- |
| 1   | `pnpm lint`, `pnpm typecheck`, `pnpm build` 통과 | 명령 실행 |      |
| 2   |                                                  |           |      |

### 1.3 공통 확인 항목

| 영역   | 확인할 것                                                            | 확인 방법           | 결과 |
| ------ | -------------------------------------------------------------------- | ------------------- | ---- |
| FSD    | 아래 레이어가 위 레이어를 import 하지 않는다                         | import 경로 검색    |      |
| FSD    | 같은 레이어 슬라이스끼리 import 하지 않는다                          | import 경로 검색    |      |
| FSD    | 슬라이스 밖에서는 `index.ts`로만 import 한다                         | import 경로 검색    |      |
| 디자인 | 색은 의미 토큰만 쓴다 (`#hex`, 팔레트 직접 사용 없음)                | `grep`              |      |
| 디자인 | 라이트/다크 둘 다 깨지지 않는다                                      | 화면 확인           |      |
| 접근성 | 글자 대비 4.5:1 이상, 키보드로 조작 가능, 아이콘 버튼에 `aria-label` | 코드와 화면 확인    |      |
| 상태   | 로딩, 빈 상태, 에러 상태가 있다                                      | 코드와 화면 확인    |      |
| 보안   | 새 의존성이 phase 문서에 적혀 있고 확인되었다                        | `package.json` diff |      |
| 보안   | 비밀값, 토큰이 코드나 커밋에 없다                                    | diff 검색           |      |

### 1.4 이번 변경에서 특히 볼 것

diff를 보고 위험해 보이는 부분, 계획에 없던 변경을 적는다.
