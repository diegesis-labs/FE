### 1.4 이번 변경에서 특히 볼 것

각 항목 끝의 **→** 뒤가 결과다.

- **CI에서 steiger가 실제로 도는지**: 로컬에서만 확인했다. PR을 열어 CI `check`의 `pnpm lint` 단계 로그에 steiger 출력이 있는지 본다. PR은 리뷰 실행 때 사용자 확인을 받고 연다. **→ 통과.** PR #9를 열었고 `249f4eb`(리뷰 수정 포함)에서 CI `check` 성공. 로그에 `$ steiger ./src`와 `✔ No problems found!`가 있음
- **전역 CSS import 위치 변경**: `main.tsx` → `App.tsx`. 스타일이 첫 화면에 그대로 적용되는지, 빌드한 CSS 크기가 `main`과 비슷한지(`dist/assets/*.css`) 확인한다. **→ 통과.** `index.css` 내용이 `main`과 같고(7,489바이트), 첫 화면 스크린샷이 `main`과 픽셀 동일
- **테마 깜빡임 방지 스크립트**: `index.html`의 저장 키(`diegesis-theme`)와 `shared/lib/theme/theme-context.ts`의 `THEME_STORAGE_KEY`가 여전히 같은지. 다크로 바꾼 뒤 새로고침할 때 흰 화면이 번쩍이지 않는지 본다. **→ 일부 통과.** 두 키가 `diegesis-theme`으로 같고, 다크에서 새로고침한 뒤 `dark` 클래스가 유지됨. 첫 페인트의 깜빡임 자체는 측정하지 못함 (3절)
- **`react-refresh` 예외 경로**: `eslint.config.js`의 예외가 `src/shared/ui/**`로 바뀌었다. `button.tsx`(컴포넌트와 `buttonVariants`를 같이 export)가 lint를 통과하는 것이 예외가 적용된다는 근거인지, 예외를 빼면 실패하는지로 확인한다. **→ 통과.** 예외 경로를 다른 곳으로 바꾸면 `button.tsx:64`에서 `react-refresh/only-export-components` 에러, 원래대로면 깨끗
- **git 이력**: `RootLayout.tsx`와 `HomePage.tsx`는 내용이 많이 바뀌어 이동이 아니라 삭제·추가로 잡힌다. `git log --follow`로 이력이 이어지는지 확인하고, 안 되면 발견 사항(낮음)으로 남긴다. **→** `HomePage.tsx`, `button.tsx`는 이어지지만 `RootLayout.tsx`는 끊김 (발견 2)
- **steiger 버전 고정 방식**: `^` 없이 정확한 버전으로 들어갔다. 0.x라 규칙이 바뀔 수 있어 고정이 오히려 맞는지, 다른 패키지와 맞출지 판단한다. **→ 고정 유지.** 0.x는 마이너 버전에서도 규칙이 바뀔 수 있어, `^`이면 설치만 다시 해도 CI가 깨질 수 있다. 올릴 때는 phase를 열어 바꾼다
- **peer 경고**: 설치 때 `tsconfck`(steiger의 하위 의존성)가 TypeScript ^5를 원한다는 경고가 났다. tsconfig `paths`(`@/*`)를 steiger가 제대로 읽는지는 1.2 #5의 위반 검출로 확인된다. 오탐이나 미탐이 없는지 본다. **→ 그대로 둠.** 별칭(`@/`) import를 제대로 해석해 위반을 잡았고 현재 코드에서 오탐 0건
- **꺼 둔 규칙**: `fsd/insignificant-slice`를 끈 것 외에 recommended 규칙이 그대로인지 `steiger.config.ts`를 확인한다. **→** recommended + `insignificant-slice` 끔 그대로였음. 리뷰 중 `import-locality`가 recommended에서 꺼져 있다는 것을 찾아 켬 (발견 1). 같이 꺼져 있는 `no-cross-imports`, `no-higher-level-imports`는 `forbidden-imports`가 이미 같은 위반을 잡아서 켜지 않음
