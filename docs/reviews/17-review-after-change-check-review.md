### 1.4 이번 변경에서 특히 볼 것

- **커밋 범위**: 검사 6은 `rev-list --no-merges base..head`의 순서를 믿는다. 브랜치에 `main`을 머지해 들어온 커밋이 섞이지 않는지 (`base`가 PR 이벤트의 `base.sha`라서 그 커밋들은 빠지는지). → 통과. 임시 저장소에서 기능 브랜치에 `main`을 머지한 뒤 `--base main`으로 돌리면 `main` 쪽 커밋은 빠지고(2개 커밋) 검사 6 통과. `main`이 더 나아간 뒤에도 같았다. 머지 커밋 안의 충돌 해결은 보지 않는다(`--no-merges`). 지난 PR에서 실제로 있었다 (발견 사항 1)
- **리뷰 문서 이름 바꾸기**: `diff-tree --name-only`가 이름 변경을 새 이름으로도 내는지 (phase 설계의 주장). 임시 저장소나 실제 커밋으로 확인한다. → 통과. 임시 저장소에서 `git mv` 커밋의 `diff-tree --name-only`가 예전 이름과 새 이름을 둘 다 낸다. 새 이름을 링크하면 그 커밋이 리뷰 문서를 바꾼 것으로 잡힌다
- **검사 5와 겹치지 않음**: 리뷰 링크가 없거나 파일이 없을 때 검사 6이 실패를 더하지 않는지 (`runChecks` 테스트와 PR #42 첫 상태). → 통과. 테스트 "리뷰 문서가 브랜치에 없으면 검사 5만 실패한다". PR #42 draft 첫 상태는 리뷰 문서가 없었지만 draft라 둘 다 실패하지 않았다
