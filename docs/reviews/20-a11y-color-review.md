### 1.4 이번 변경에서 특히 볼 것

- **포커스를 빼앗지 않는가**: `focus-on-navigate`는 포커스가 `<body>`일 때만 옮긴다. 목차 서랍(Radix, 포커스를 가둠)에서 챕터를 고르면 경로는 그대로라 옮기지 않아야 한다. 서랍이 닫힌 뒤 포커스가 목차 버튼으로 돌아가는지. → 통과. 키보드로 3장을 고르면 `?chapter=3`, 포커스는 `목차` 버튼
- **기다림이 남지 않는가**: `MutationObserver`는 `h1`을 찾거나 5초가 지나거나 다음 이동이 오면 멈춘다. 빠르게 두 번 옮겼을 때 앞 이동의 기다림이 뒤 화면에 포커스를 주지 않는지 (코드 읽기). → 통과. 새 이동마다 `stopWatching`이 앞 관찰·타이머·프레임을 모두 멈춘다(`7c7ca58`에서 프레임 취소도 `stop`에 모음). 책을 누르고 30ms 만에 뒤로 가도 포커스는 목록 `h1`
- **로그인으로 보내기**: 로그아웃 뒤(`/login`으로 이동)와 리더에서 401로 보내질 때 포커스가 로그인 화면의 `h1`(`Diegesis`)로 가는지. 첫 화면 열기에서 로그인으로 보내질 때는 가지 않는지. → 통과. 로그아웃 뒤, 리더에서 세션이 끊긴 채 다른 챕터를 열어 401로 보내질 때 모두 `h1`(`Diegesis`), 제목 `로그인 · Diegesis`. 첫 화면은 1.2절 9
- **라우트 에러 화면**: 이동 중에 라우트 에러가 나면 에러 화면의 `h1`에 포커스가 가는지, 그 화면 제목이 정해지는지. → 처음엔 실패, 고친 뒤 통과 (2절 1). 리더에서 `broken`으로 바꾸고 `책 목록`을 누르면 제목은 맞지만 포커스가 `<body>`였다. 고친 뒤 `h1`(`화면을 표시하지 못했습니다`)
- **`tabindex="-1"`이 남는 것**: `h1`을 마우스로 눌러도 링이 생기지 않는지, Tab 순서에 들어가지 않는지. → 통과. 마우스로 옮긴 뒤·`h1`을 누른 뒤 모두 `:focus-visible` 아님, Tab 12번에 `h1` 없음. 키보드로 옮기면 `h1`에 2px 링(의도한 대로)
- **챕터 제목 알림의 상태 비교**: 렌더 중 `setIntro`가 무한 렌더를 만들지 않는지(조건이 한 번만 참). 챕터 전환 중(`layout`이 비었다 생김) 제목이 빠지지 않는지. 개발 콘솔 경고 확인. → 통과. `setIntro`는 `chapterNo`가 다를 때만 불리고 바로 같은 값이 되어 한 번만 참. →로 책 끝까지 넘기는 동안 콘솔 오류·경고 0개. 전환 뒤 첫 쪽에 제목이 들어감(1.2절 10)
- **`text-foreground/50`**: 다크에서 흐린 아이콘이 보이는지(스크린샷). hover·포커스 때 글자색이 되살아나지 않는지. → 통과. 다크 끝 쪽 키보드 포커스 상태에서 `cream-50` 50%(`이전 페이지`는 100%), 스크린샷에서 흐린 아이콘과 링이 보인다. hover는 `pointer-events-none`이라 일어나지 않음(1.2절 3)
- **`control-border`가 닿는 곳**: `outline`을 쓰는 곳 셋(에러 안내의 `다시 시도`, 없는 페이지 `홈으로`, 라우트 에러 `새로고침`). hover 때 테두리가 사라지고 반전되는지(그대로). → 통과. `홈으로` hover 때 테두리 투명, 바탕 `charcoal-800`
- **design-system 문서가 코드와 같은가**: 1.5·1.7 값과 `index.css`, 4.1의 `aria-disabled` 설명과 `button.tsx`. → 통과. `control-border` `sand-600`/`pine-300`이 셋 다 같고, 4.1의 "`ghost`에서 `foreground` 50%, `opacity` 쓰지 않음"이 `button.tsx`와 같다. 4.6의 화면 이동 뒤 포커스 설명이 `focus-on-navigate.ts`와 같다

## 3. 확인 못 한 것

- 실제 화면 낭독기(VoiceOver, NVDA)로 쪽 알림·화면 이동 뒤 제목을 들어 보는 것. DOM(같은 `aria-live` 노드, 문장, 포커스 위치)으로만 확인했다.
- 실제 BE로 로그아웃: 목에서만 확인했다. BE 로그아웃은 언제나 204라 요청 수와 포커스는 같을 것으로 본다.
- 고대비 모드(forced-colors)에서 목차 막대와 흐린 버튼: 막대는 테두리라 남지만 흐린 글자색은 시스템 색으로 바뀌어 구분되지 않을 수 있다. 낭독기에는 `aria-disabled`로 전해진다.

## 4. 결론

수정 후 통과. 리뷰 중 발견 1건(중간, 라우트 에러 화면에서 포커스가 사라짐)을 고쳤다(`7c7ca58`). 키보드로 책 끝까지 가도 포커스가 남고, 화면을 옮기면 새 화면의 제목에 포커스가 가며, 쪽 알림은 같은 영역에서 챕터가 바뀔 때만 제목을 읽는다. 목차 막대, outline 테두리, 로그인 안내 제목 모두 라이트·다크에서 기준을 넘는다. 남은 일: PR을 열고 CI `check` 확인, 머지(사용자 요청 뒤), 머지 뒤 `fe-main` 확인과 태그 정리. #47의 나머지 MEDIUM 7건은 phase 21.
