# 가드레일: 규칙과 강제 수단

> 관련 phase: [04 가드레일 lint](phases/04-guardrail-lint.md), [05 작업 절차 CI 검사](phases/05-process-check.md), [11 Confluence 회의록 확인](phases/11-confluence-gate.md)

[CLAUDE.md](../CLAUDE.md)의 규칙마다 **무엇이 강제하는지** 적은 표다. 강제 수단이 "없음"인 규칙은 글로만 있는 규칙이라, 사람과 에이전트가 읽고 지켜 주기를 바랄 수밖에 없다.

규칙을 고치거나 새로 만들 때:

- 같은 실수를 두 번 고치게 되면, 규칙 문서에 한 줄을 더하기 전에 lint·타입·테스트로 만들 수 있는지 먼저 본다.
- 새 lint 규칙은 에러 메시지에 **대신 쓸 것**을 적는다.
- ESLint 가드레일을 추가하면 `scripts/check-guardrails.mjs`에 "걸려야 하는 사례"와 "통과해야 하는 사례"를 함께 넣는다.
- 강제 수단이 바뀌면 이 표를 같이 고친다.

"Claude Code 훅"은 `.claude/settings.json`의 권한 규칙과 `.claude/hooks/guard.mjs`, `.claude/hooks/confluence-gate.mjs`다. Claude Code가 명령을 실행하거나 파일을 고치기 **전에** 막거나 사용자 확인을 받는다. Claude에게만 걸리고 사람의 터미널 작업에는 걸리지 않는다. 판정 목록과 빈틈은 [Phase 05](phases/05-process-check.md)와 [Phase 11](phases/11-confluence-gate.md)의 "Claude Code 훅" 절에 있다.
