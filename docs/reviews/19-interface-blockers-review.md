### 1.4 이번 변경에서 특히 볼 것

- **스크롤된 상태의 쪽 넘김**: 320×180에서 문서를 스크롤한 뒤 ←→로 넘겼을 때 쪽이 정확히 한 쪽씩 옮겨 가는지(띠의 `translateX`가 쪽 간격의 배수인지). 스크롤 위치가 그대로인지 (phase 위험 2). → 통과. 124px 스크롤한 채 →: `translateX` 0 → −320(쪽 간격 288 + 32), 1쪽 → 2쪽, 스크롤 124 그대로. ←로 0에 돌아온다. 처음 스크린샷에서 본문 왼쪽이 잘려 보였는데, 전체 페이지 캡처가 화면 높이를 바꾸며 다시 잰 순간이었다. 화면 크기 그대로의 캡처에서는 잘림이 없다
- **터치 스크롤**: 무대는 `touch-pan-y`라 세로 끌기를 브라우저에 맡긴다. 낮은 화면에서 무대를 세로로 끌면 문서가 스크롤되는지 (터치 에뮬레이션). → 통과. CDP 터치 스크롤 제스처(무대 위, 80px 위로)로 `scrollY` 0 → 81, 쪽은 그대로 1쪽
- **챕터 에러 위의 스와이프**: 에러 상태에서도 무대에 스와이프 핸들러가 붙어 있다. 에러 영역을 가로로 끌거나 눌렀을 때 오류가 나거나 쪽이 넘어가지 않는지. → 통과. 에러 안내를 가로로 끌고 눌러도 주소·안내가 그대로이고, 콘솔 오류는 목이 낸 500 응답 기록뿐(스크립트 오류 없음)
- **`<a href="/">`**: 라우트 에러 화면에서만 문서를 새로 불러온다. `/login`에서 난 에러에서 누르면 `/` → 로그인 확인 → `/login`으로 가는지. → 통과(간접). 로그아웃 상태로 `/`를 새로 열면 `/login`으로 간다. `/login`에서 실제로 화면 오류를 내 보지는 못했다(3절)
- **개발 중 원인 찾기**: 화면에서 예외 메시지를 뺐다. 개발 모드 콘솔에 원인(React Router의 에러 로그)이 남는지. → 통과. 개발 서버와 PR #46 미리보기(운영 빌드, 데모 모드) 모두 콘솔에 `TypeError: Cannot read properties of undefined (reading 'length')`와 "React Router caught the following error during render"가 남는다
- **`min-h-76`과 책 로딩·에러**: 바깥 틀의 최소 높이가 책 로딩 뼈대와 책 에러 화면에도 걸린다. 320×180에서 이상하지 않은지. → 통과. 로딩은 1.3절 상태, 에러는 1.2절 3. 에러 안내가 남은 높이(304px) 안에서 스크롤된다
- **phase 18 기록**: 18 문서·18 리뷰 문서에 적은 머지 뒤 결과(`c73bf29`, `diegesis-fe-c73bf29-50b16e`, `pr-44` 태그 없음)가 `gcloud`와 같은지. → 통과. `gcloud builds list`: `c73bf29`의 `fe-main` SUCCESS. `gcloud run services describe diegesis-fe`: 트래픽 100% `diegesis-fe-c73bf29-50b16e`, `pr-44` 태그 없음. 지금은 이 PR의 `pr-46` 태그 리비전이 있다(머지 뒤 지운다)

## 3. 확인 못 한 것

- 실제 휴대폰(iOS Safari, Android Chrome)과 브라우저 확대: 화면 크기를 400% 확대와 같게 맞춘 Chromium으로만 봤다. 실제 확대 시 주소창이 늘고 주는 것(`dvh`)과 함께 움직이는지는 보지 못했다.
- 화면 낭독기로 라우트 에러 화면과 챕터 에러를 읽어 보는 것.
