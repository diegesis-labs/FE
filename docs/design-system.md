# Diegesis 디자인 시스템

> 관련 이슈: [#4 이미지 보드 및 컬러 팔레트 공유](https://github.com/diegesis-labs/FE/issues/4), [#3 UI/UX 설계 및 와이어프레임](https://github.com/diegesis-labs/FE/issues/3)
>
> 레퍼런스: Aesop 한국 사이트의 [선물 페이지](https://kr.aesop.com/kr/gifts.html). 사이트의 CSS에서 색상·글자 크기·간격·모션 값을 뽑아 분위기를 참고했다.

## 0. 원칙

레퍼런스는 **분위기와 수치를 참고만** 한다. 브랜드 자산은 가져오지 않는다.

- 로고, 브랜드명, 사진·일러스트, 아이콘 파일은 쓰지 않는다.
- 레퍼런스 폰트(Suisse Int'l, Zapf Humanist)는 유료 라이선스라 쓰지 않고, 무료 폰트로 대체한다 (3장).
- 색상과 수치는 우리 서비스에 맞게 이름을 다시 붙이고, 필요하면 조정한다.

이 디자인 시스템이 지향하는 느낌은 다음과 같다.

1. **종이 같은 바탕.** 순백 대신 따뜻한 크림색 바탕에 짙은 차콜색 글자를 쓴다. 대비는 높지만 눈이 편하다.
2. **장식을 덜어낸다.** 그림자, 둥근 모서리, 그라데이션을 거의 쓰지 않는다. 면과 얇은 선으로 구분한다.
3. **여백과 글자로 위계를 만든다.** 색을 많이 쓰지 않는다. 강조는 굵기, 크기, 세리프 서체, 여백으로 한다.
4. **움직임은 조용하게.** 짧은 색 전환 정도만 쓰고, 튀는 애니메이션은 쓰지 않는다.

## 1. 색상

### 1.1 기본 팔레트

Tailwind 기본 팔레트(`stone`, `red` 등)와 이름이 겹치지 않게 지었다. `bg-cream-100`, `text-clay-600`처럼 쓸 수 있다.

### 1.2 브랜드 포인트 컬러 (clay)

크림 바탕과 어울리는 따뜻한 **점토색 갈색**을 포인트로 쓴다. 레퍼런스에 드물게 쓰인 갈색(`#965D34`)을 조금 어둡게 조정해서, 크림 면 3단계 어디에 올려도 글자 대비 4.5:1을 넘게 했다. 금색(`#BF900D`)도 후보였지만 크림 바탕에서 대비가 2.87:1이라 글자에 쓸 수 없어서 뺐다.

**포인트 컬러는 아껴 쓴다.** 무채색 화면에 한두 군데만 쓸 때 눈에 띈다.

- 쓰는 곳: 섹션 위의 작은 머리글(eyebrow), 새 기능·상태 배지, 선택된 탭이나 현재 메뉴 표시, 화면에서 가장 강조할 버튼 하나(`variant="brand"`)
- 쓰지 않는 곳: 본문 링크, 넓은 배경 면, 오류나 경고 (오류는 `brick`)
- 기본 버튼은 계속 차콜(`primary`)이다. 브랜드 버튼은 **한 화면에 하나 이하**로 쓴다.

```tsx
<p className="text-xs font-medium text-brand">새 기능</p>
<Button variant="brand">시작하기</Button>
<span className="bg-brand px-2 py-0.5 text-xs text-brand-foreground">NEW</span>
```

### 1.4 다크 모드

MVP에 포함한다. 라이트의 크림·차콜 톤을 그대로 뒤집되, 순검정 대신 **따뜻한 먹색**(`ink`)을 바탕으로 쓴다.

- 사용자는 헤더의 버튼으로 **시스템 설정 → 라이트 → 다크** 순으로 바꿀 수 있다. 기본값은 시스템 설정을 따른다.
- 선택은 `localStorage`(`diegesis-theme` 키)에 저장된다.
- `index.html`의 작은 스크립트가 React보다 먼저 테마를 적용해서, 새로고침할 때 화면이 하얗게 깜빡이지 않는다.
- 구현: `src/shared/theme/` (`ThemeProvider`, `useTheme`), `src/components/ThemeToggle.tsx`. `<html>`에 `dark` 클래스를 붙이는 방식이라 Tailwind의 `dark:` 접두사도 쓸 수 있다. 하지만 **의미 토큰을 쓰면 `dark:`를 쓸 일이 거의 없다.**
- 사진처럼 다크에서 너무 밝아 보이는 요소는 `dark:brightness-90` 정도로 살짝 낮춘다.

### 1.5 대비 (WCAG)

본문 글자는 4.5:1 이상이어야 한다. 각 바탕 3단계(기본 / 보조 면 / hover 면) 기준으로 계산했다.

**라이트** (바탕 `cream-50` / `cream-100` / `cream-200`)

| 글자 색             | 대비               | 판정                                                 |
| ------------------- | ------------------ | ---------------------------------------------------- |
| `charcoal-800`      | 12.46 / 11.52 / –  | 통과 (모든 글자)                                     |
| `charcoal-500`      | 5.66 / – / 4.75    | 통과. `cream-200` 위 작은 글자는 `charcoal-800` 권장 |
| `sand-600`          | 5.31               | 통과                                                 |
| `clay-600` (브랜드) | 6.05 / 5.59 / 5.07 | 통과                                                 |
| `brick-600` (오류)  | 4.76               | 통과                                                 |
| `#999999`           | 2.81               | **실패**. 글자에 쓰지 않는다                         |
| `sand-400`          | 1.90               | **실패**. 장식 선에만 쓴다                           |

**다크** (바탕 `ink-950` / `ink-900` / `ink-800` / `ink-700`)

| 글자 색               | 대비                          | 판정 |
| --------------------- | ----------------------------- | ---- |
| `cream-50`            | 16.28 / 14.95 / 13.43 / 11.61 | 통과 |
| `#A8A79C` (보조 글자) | 6.82 / 6.26 / 5.62 / 4.86     | 통과 |
| `clay-300` (브랜드)   | 6.74 / 6.19 / 5.56 / 4.80     | 통과 |
| `brick-300` (오류)    | 6.71 / 6.17 / 5.54 / 4.79     | 통과 |

새 색을 추가할 때도 이 표처럼 대비를 확인하고 여기에 적는다.

## 2. 레이아웃

### 2.1 간격

4px 단위를 쓴다. Tailwind 기본 간격(`1` = 4px)과 같으니 클래스를 그대로 쓰면 된다.

| 값   | Tailwind | 주 용도                              |
| ---- | -------- | ------------------------------------ |
| 4px  | `1`      | 아이콘과 글자 사이                   |
| 8px  | `2`      | 촘촘한 요소 사이                     |
| 12px | `3`      | 폼 라벨과 입력창 사이                |
| 16px | `4`      | 컴포넌트 안쪽 여백, 모바일 좌우 여백 |
| 24px | `6`      | 카드 안쪽 여백, 버튼 좌우 여백       |
| 40px | `10`     | 섹션 안 블록 사이                    |
| 60px | `15`     | 섹션 사이 (모바일)                   |
| 96px | `24`     | 섹션 사이 (데스크톱)                 |

여백은 넉넉하게 쓴다. 고민되면 한 단계 큰 값을 고른다.

### 2.2 컨테이너와 브레이크포인트

- 콘텐츠 최대 너비 **1200px** (`max-w-300`), 좌우 여백 모바일 16px / 데스크톱 40px.
- 긴 글은 읽기 편하도록 **최대 660px** (`max-w-165`).
- 브레이크포인트는 Tailwind 기본값을 쓴다. 레퍼런스도 768px, 1024px에서 나뉜다.

| 이름   | 너비    | 레이아웃             |
| ------ | ------- | -------------------- |
| (기본) | ~767px  | 1열, 모바일          |
| `md`   | 768px~  | 2열                  |
| `lg`   | 1024px~ | 3~4열, 데스크톱 헤더 |

### 2.3 모서리와 그림자

- **모서리는 각지게 둔다.** 버튼, 입력창, 카드 모두 `rounded-none`이 기본이다. 아바타나 아이콘 버튼처럼 원형이 필요한 곳만 `rounded-full`을 쓴다.
- **그림자는 쓰지 않는다.** 면의 색 차이(`cream-50` → `cream-100`)와 1px 선으로 구분한다. 팝오버, 드롭다운처럼 위에 떠야 하는 것만 아주 옅은 그림자 `0 0 3px rgb(51 51 51 / 0.2)`를 쓴다.

## 3. 타이포그래피

### 3.1 서체

| 역할                 | 서체             | 대체 이유                                                                                                             |
| -------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------- |
| 본문, UI (Sans)      | **Pretendard**   | 레퍼런스의 Suisse Int'l처럼 담백한 산세리프. 한글과 영문이 함께 잘 맞고 무료(OFL).                                    |
| 제목, 인용 (Display) | **Gowun Batang** | 레퍼런스는 Zapf Humanist(Optima 계열)로 제목에 손글씨 같은 온기를 준다. 한글에서 비슷한 결을 내는 무료 바탕체로 대체. |

- Tailwind 클래스: 본문 `font-sans`, 제목 `font-display`.
- 두께는 Regular(400)와 Medium(500)만 쓴다. Bold는 거의 쓰지 않는다. 위계는 크기와 서체로 만든다.
- 영문 대문자 변환(`uppercase`)이나 넓은 자간은 쓰지 않는다.

### 3.2 글자 크기

레퍼런스는 기본 글자가 12px로 작다. 한글은 같은 크기에서 더 작아 보여서 **본문은 14~16px**으로 한 단계 키웠다.

| 이름      | 크기 / 줄간격 | 서체        | 용도              |
| --------- | ------------- | ----------- | ----------------- |
| `display` | 36px / 1.2    | Display     | 히어로 제목       |
| `h1`      | 30px / 1.25   | Display     | 페이지 제목       |
| `h2`      | 24px / 1.33   | Display     | 섹션 제목         |
| `h3`      | 18px / 1.4    | Sans Medium | 카드 제목, 소제목 |
| `body-lg` | 16px / 1.6    | Sans        | 긴 글 본문        |
| `body`    | 14px / 1.5    | Sans        | 기본 본문, UI     |
| `caption` | 12px / 1.5    | Sans        | 메타 정보, 라벨   |

모바일에서는 `display`, `h1`을 한 단계씩 줄인다 (`text-3xl md:text-4xl`).

```tsx
<h1 className="font-display text-3xl leading-tight">페이지 제목</h1>
<h2 className="font-display text-2xl leading-snug">섹션 제목</h2>
<h3 className="text-lg font-medium">카드 제목</h3>
<p className="text-sm text-muted-foreground">설명 텍스트</p>
```

## 4. 컴포넌트

shadcn/ui 컴포넌트를 쓰되, 아래 규칙에 맞게 `src/components/ui/`의 코드를 고친다.

### 4.1 버튼

| 종류                  | 기본                         | hover                        | 용도                                               |
| --------------------- | ---------------------------- | ---------------------------- | -------------------------------------------------- |
| Primary (`default`)   | 차콜 바탕 + 크림 글자        | `charcoal-900`               | 화면에서 가장 중요한 동작 1개                      |
| Brand (`brand`)       | 포인트 컬러 바탕 + 크림 글자 | `brand-hover`                | 화면에서 가장 강조할 동작. **한 화면에 하나 이하** |
| Secondary (`outline`) | 투명 바탕 + `line` 테두리    | 차콜 바탕 + 크림 글자 (반전) | 보조 동작                                          |
| Text (`link`)         | 밑줄 글자                    | 진하게                       | 덜 중요한 동작, 문장 속 링크                       |
| Destructive           | `destructive` 바탕           | 조금 어둡게                  | 삭제 등 되돌릴 수 없는 동작                        |

- 모서리 없음, 높이 44px, 좌우 여백 24px, 글자 14px Medium.
- 주요 버튼은 **최소 너비 200px**으로 넉넉하게. 모바일에서는 가로 전체(`w-full`).
- 아이콘만 있는 버튼은 40×40px.
- 전환: `background-color`와 `color`를 0.25초 `ease-out`.

### 4.2 입력창

- 크림 바탕, 1px `line` 테두리, 모서리 없음, 높이 44px, 좌우 여백 16px.
- 포커스: 테두리를 `charcoal-800`으로 진하게. 오류: 테두리와 아래 메시지를 `destructive`로.
- 비활성: 바탕 `cream-100`.
- 라벨은 입력창 위에 12px로 둔다. placeholder를 라벨 대신 쓰지 않는다.

### 4.3 카드

- 테두리나 그림자 없이 **이미지 + 글자** 조합으로 만든다. 레퍼런스의 상품 카드처럼 이미지 아래에 제목(14~16px Medium)과 설명(14px, `muted-foreground`, 2줄 말줄임)을 둔다.
- 면을 나눠야 하면 `cream-100` 바탕을 쓴다.
- hover 때 이미지를 살짝 확대(`scale-[1.02]`, 0.3초)하는 정도만 허용한다.

### 4.4 링크

- 본문 속 링크는 밑줄을 그어 구분한다 (색을 바꾸지 않음).
- 내비게이션 같은 UI 링크는 밑줄 없이, hover 때 밑줄을 표시한다.

### 4.5 알림과 안내

- 안내/성공: `bg-accent` + `text-foreground`.
- 오류: `text-destructive` 글자, 필요하면 `bg-destructive` + `text-destructive-foreground`.
- 토스트는 `bg-primary` + `text-primary-foreground`(라이트에선 차콜, 다크에선 크림), 화면 아래에 띄운다.

## 5. 모션

| 대상                              | 시간  | 이징          |
| --------------------------------- | ----- | ------------- |
| 색 변화 (버튼, 링크 hover)        | 250ms | `ease-out`    |
| 배경 전환                         | 300ms | `ease-out`    |
| 이동, 확대 (드로어, 이미지 hover) | 300ms | `ease-in-out` |
| 나타남 (페이드인)                 | 400ms | `ease`        |

- 튕기는(bounce) 효과, 큰 회전, 반복 애니메이션은 쓰지 않는다.
- `prefers-reduced-motion`이 켜져 있으면 이동과 확대를 끈다 (Tailwind `motion-safe:` 접두사 사용).

## 6. 로고와 이미지

MVP에는 **로고와 이미지 보드가 없다.**

- 로고 대신 서비스명 "Diegesis"를 제목 서체(`font-display`)로 쓴 **워드마크**를 쓴다. 헤더와 파비콘 자리가 여기에 해당한다.
- 화면은 사진 없이 **크림 면, 여백, 글자**로 구성한다. 이미지가 들어갈 자리에는 `bg-muted` 면을 두고, 필요하면 아이콘이나 짧은 문구를 넣는다.
- 사용자가 올리는 이미지(콘텐츠)는 예외다. 비율을 고정하고(`aspect-*`) `object-cover`로 채운다.
- 아이콘은 `lucide-react`를 쓰고 선 두께는 1.5로 얇게, 크기는 16px 또는 20px.
- 아이콘 색은 글자 색(`currentColor`)을 따른다.

## 7. 코드에서 쓰는 법

- 색은 의미 토큰 클래스만 쓴다: `bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`, `bg-accent`, `text-brand` 등. `#333` 같은 값을 직접 쓰지 않는다.
- 팔레트 원색이 꼭 필요하면 `bg-cream-100`, `text-sand-600`처럼 팔레트 클래스를 쓴다. 이때는 다크 모드 값도 직접 챙겨야 한다.
- 토큰 정의 위치: `src/index.css` (`@theme` 팔레트, `:root` 라이트, `.dark` 다크).
- 테마: `useTheme()`으로 현재 테마를 읽거나 바꾼다.
- 폰트 로딩: `index.html`에서 Pretendard(jsDelivr), Gowun Batang(Google Fonts)을 불러온다.
