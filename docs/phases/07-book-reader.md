## 목표

`/books/:bookId`가 전자책 리더가 된다. 본문이 화면 크기에 맞는 페이지로 나뉘고, 버튼·키보드·화면 탭으로 페이지를 넘기며, 챕터 끝에서 다음 챕터로 이어진다. 페이지마다 "화면에 보이는 첫 문장과 마지막 문장 번호"를 계산해 두어, 다음 phase에서 위치 알림 API(음악 선곡)에 그대로 쓸 수 있다.

## 배경

- BE PRD의 핵심 시나리오는 "독자가 페이지를 넘기면 그 장면에 맞는 음악이 흐른다"이다. 위치 알림 API(`POST /api/books/{id}/position`)는 화면에 보이는 첫·마지막 문장 번호를 받는다 ([BE API.md](https://github.com/diegesis-labs/BE/blob/main/docs/API.md) 4.6, 4.7절).
- BE는 본문을 문단 → 문장 구조로 주고, 페이지 나누기는 FE가 한다고 정했다.
- 페이지 방식으로 정한 이유: 페이지를 넘기는 순간이 곧 "보이는 범위가 바뀌는 순간"이라 위치 알림 시점이 분명하다. 스크롤은 범위가 계속 바뀌어 묶어 보내는 규칙이 따로 필요하다.

## 범위

### 하는 것

- 챕터 본문을 화면 크기에 맞춰 페이지로 나누기 (CSS 다단 방식, 아래 설계)
- 페이지 넘기기: 이전/다음 버튼, 키보드(`←` `→` `PageUp` `PageDown` `Space`), 화면 왼쪽·오른쪽 영역 탭
- 챕터 경계: 마지막 페이지에서 다음 → 다음 챕터 첫 페이지, 첫 페이지에서 이전 → 이전 챕터 마지막 페이지
- 위치를 문장 번호로 URL에 저장 (`?chapter=2&s=412`). 새로고침, 창 크기 변경, 글꼴 로딩 뒤에도 같은 문장이 보이는 페이지로 돌아온다
- 첫 진입 위치: URL → `last_position` → 1장 첫 페이지
- 페이지마다 보이는 문장 범위(`chapter_no`, `first_sentence`, `last_sentence`) 계산
- 리더 상단 막대: 책 목록으로 돌아가기, 책 제목·챕터 제목, 목차 열기, 테마 버튼
- 목차 서랍: 챕터 목록, 현재 챕터 표시, 눌러서 이동
- 진행 표시: 챕터 안 쪽수(`3 / 12`)
- 리더 전용 레이아웃 (일반 헤더와 `main` 여백 없이 화면 전체 사용)

### 하지 않는 것

- 위치 알림 API 호출, 음악 재생·멈춤 버튼, 반응 기록 → 다음 phase (음악)
- 마지막 읽은 위치를 서버에 저장 (위치 알림이 저장을 겸하므로 음악 phase에서 함께)
- 글자 크기·줄 간격·서체 설정, 두 쪽 펼침 보기, 책갈피, 형광펜, 검색
- 페이지 넘김 애니메이션 (바로 바뀐다. 필요하면 와이어프레임 뒤에 추가)
- 스와이프 제스처 (탭 영역으로 대신함)
- 테스트 프레임워크 추가 (아래 열린 질문)

### 페이지 나누기 방식

CSS 다단(multi-column)을 쓴다. epub 리더들이 쓰는 방식이다.

1. 본문 영역의 높이를 화면에 고정하고(`100svh` − 상단 막대 − 아래 막대), `column-width`를 영역 너비로, `column-gap`을 좌우 여백으로 둔다. 브라우저가 글을 세로로 채우다 넘치면 오른쪽 단으로 넘긴다. 단 하나가 한 페이지다.
2. 바깥 영역은 `overflow: hidden`, 안쪽을 `translateX(-페이지 × (너비 + 간격))`로 옮겨 한 단만 보인다.
3. 페이지 수 = `scrollWidth / (너비 + 간격)` (올림).
4. 문장마다 `<span data-sentence-idx>`가 있다 (Phase 06). 각 문장의 `getClientRects()` 위치로 어느 페이지(들)에 걸치는지 구해 `문장 → 페이지` 표를 만든다. 페이지의 보이는 범위는 그 페이지에 조금이라도 걸친 첫 문장과 마지막 문장이다.
5. 이 표는 영역 크기, 글꼴 로딩, 챕터 본문이 바뀔 때만 다시 만든다. 다시 만든 뒤에는 URL의 문장 번호 `s`가 들어 있는 페이지로 이동한다. 그래서 창 크기를 바꿔도 읽던 문장이 사라지지 않는다.

본문 서체와 크기: 디자인 시스템의 `body-lg`(Pretendard 16px / 1.6)를 기본으로, 줄 간격만 1.8로 넓힌다. 한 줄 최대 너비 `max-w-165`(660px). 데스크톱에서는 가운데 한 단, 모바일에서는 좌우 16px 여백.

### 위치 상태

- URL이 기준이다: `/books/:bookId?chapter=N&s=M`. `s`는 현재 페이지의 첫 문장 번호.
- 페이지를 넘길 때 `setSearchParams(..., { replace: true })`로 바꾼다. 페이지마다 방문 기록이 쌓이지 않게 한다. 챕터를 바꿀 때만 기록을 남긴다(뒤로 가기로 이전 챕터).
- 잘못된 값: `chapter`가 범위 밖이면 1장, `s`가 그 챕터 범위 밖이면 챕터 첫 페이지.

### 조작과 접근성

| 동작        | 입력                                                      |
| ----------- | --------------------------------------------------------- |
| 다음 페이지 | 오른쪽 버튼, `→`, `PageDown`, `Space`, 화면 오른쪽 1/3 탭 |
| 이전 페이지 | 왼쪽 버튼, `←`, `PageUp`, `Shift+Space`, 화면 왼쪽 1/3 탭 |
| 목차        | 상단 막대 버튼 → 서랍(포커스 가둠, `Esc`로 닫기)          |

- 버튼은 아이콘만 있으므로 `aria-label`("이전 페이지", "다음 페이지")을 단다. 책의 처음·끝에서는 비활성.
- 쪽수 표시는 `aria-live="polite"`로 바뀔 때 읽어 준다 ("12쪽 중 3쪽").
- 키보드 단축키는 목차 서랍이 열려 있거나 입력창에 포커스가 있으면 무시한다.
- 화면 탭 영역은 버튼과 별개인 보조 수단이라 스크린 리더에는 숨긴다(`aria-hidden`).

### 화면과 상태

- 로딩: 책 정보 로딩 중에는 상단 막대 자리 스켈레톤, 본문 로딩 중에는 본문 자리 스켈레톤 줄. 페이지 계산 전에는 본문을 숨겨 깜빡임을 막는다.
- 에러: Phase 06 규칙(401, 404, 그 밖 + 다시 시도)을 리더 레이아웃 안에서 보여 준다. 본문만 실패하면 상단 막대와 목차는 그대로 쓸 수 있다.
- 다음 챕터 본문은 현재 챕터의 마지막 2쪽에 이르면 미리 받는다(`prefetchQuery`, 페이지 넘김 핸들러에서).
- 책의 마지막 페이지: "마지막 페이지입니다" 문구와 "책 목록으로" 링크.

### 새 의존성

없음. 목차 서랍은 shadcn `sheet`(이미 설치된 `radix-ui`의 Dialog)로 만든다.

## 위험과 열린 질문

- **CSS 다단 계산의 브라우저 차이**: Safari는 다단에서 `getClientRects()`와 `scrollWidth`가 다르게 나오는 경우가 있다. Chrome·Safari·Firefox에서 확인하고, 문제가 크면 문장 단위로 직접 높이를 재서 나누는 방식으로 바꾼다 (계획 변경으로 기록).
- **문단이 페이지를 넘어갈 때**: 한 문장이 두 페이지에 걸치면 두 페이지 범위에 모두 들어간다. BE가 이 겹침을 괜찮게 보는지 음악 phase 전에 BE와 확인한다.
- **본문 서체**: 소설 본문은 바탕체(`font-display`, Gowun Batang)가 더 어울릴 수 있다. 디자인 시스템은 본문을 Sans로 정했으므로 이 phase는 Sans로 하고, #3 와이어프레임에서 정해지면 바꾼다.
- **테스트**: 문장 → 페이지 표 계산은 순수 함수로 떼어 낼 수 있어 단위 테스트를 붙이기 좋다. 다만 테스트 프레임워크(Vitest)는 새 의존성이라 따로 phase를 열지 정한다. 이 phase는 브라우저 확인으로 검증한다.
- **페이지 넘김 연타**: 위치 알림을 얼마나 묶어 보낼지는 BE가 FE와 합의할 항목으로 남겨 두었다 (API.md 5절). 이 phase는 범위 계산까지만 하고, 묶는 규칙은 음악 phase에서 정한다.
