### 1.4 이번 변경에서 특히 볼 것

- **커밋 범위**: 검사 6은 `rev-list --no-merges base..head`의 순서를 믿는다. 브랜치에 `main`을 머지해 들어온 커밋이 섞이지 않는지 (`base`가 PR 이벤트의 `base.sha`라서 그 커밋들은 빠지는지).
- **리뷰 문서 이름 바꾸기**: `diff-tree --name-only`가 이름 변경을 새 이름으로도 내는지 (phase 설계의 주장). 임시 저장소나 실제 커밋으로 확인한다.
- **검사 5와 겹치지 않음**: 리뷰 링크가 없거나 파일이 없을 때 검사 6이 실패를 더하지 않는지 (`runChecks` 테스트와 PR #42 첫 상태).
- **예외 줄 + draft**: 둘 다일 때 알림이 맞는지. 예외 PR에 검사 6 결과 줄이 아예 없는지.
- **`findLastIndex`**: CI의 Node 버전(`.nvmrc` 24)에서 쓸 수 있는지.
- **이미 머지된 PR 전부에 돌린 결과**: #5 실패가 검사의 오탐이 아닌지 다시 본다 (설명은 01 리뷰만 링크, 마지막 변경은 02 리뷰에 기록).
- **문서 수정 뒤 실패(phase 위험 2)**: 리뷰 결과 뒤에 `docs/architecture.md`를 고치면 실패하는 것이 의도대로 문서에 적혀 있는지 (CLAUDE.md·PR 템플릿에서 사용자가 알 수 있는지).
- **이 PR 자신**: 마지막 계획·리뷰 문서 밖 커밋이 `d865a67`이고, 리뷰 결과 커밋이 그 뒤에 오는지. 리뷰 중 코드를 고치면 리뷰 결과 커밋을 다시 그 뒤에 둔다.
- **phase 16 기록**: 16 문서·16 리뷰 문서에 적은 머지 뒤 결과(`332a9ad`, `diegesis-fe-332a9ad-8e5354`)가 `gcloud builds list`, `gcloud run services describe`와 같은지.
