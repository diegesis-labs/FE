### 1.4 이번 변경에서 특히 볼 것

- **CI의 git**: `--remerge-diff`는 git 2.36부터다. PR #44 CI 로그의 git 버전. 이 PR에는 머지 커밋이 없어서 CI에서 `--remerge-diff`가 실제로 불리지는 않는다 (확인 못 함 후보). → 통과(버전). PR #44 CI 로그: git 2.56.1, ubuntu-26.04. 이 PR에 머지 커밋이 없어 CI에서 `--remerge-diff`가 실제로 불리지는 않았다 (3절)
- **`--remerge-diff --name-only` 출력**: 파일 이름만 나오는지, 충돌 표시나 머리말 줄이 섞이지 않는지. 이름을 바꾼 파일, 지운 파일의 충돌. → 통과. 임시 저장소에서 출력 바이트를 보면 `src/a.ts\n src/del.ts\n`처럼 파일 이름 줄만 있다. 수정/삭제 충돌도 파일 이름으로 나오고, 자동으로 된 이름 바꾸기는 나오지 않는다
- **커밋 순서**: `--parents`를 붙여도 `rev-list --reverse` 순서가 `--no-merges` 때와 같은지 (머지가 아닌 커밋끼리의 순서). → 통과. 머지 커밋이 있는 PR 6개에서 `--parents`로 모아 머지를 뺀 순서가 `--no-merges` 순서와 같다
- **검사 4**: 첫 커밋이 머지여도 "코드를 바꾼 첫 커밋"이 머지가 아닌 커밋으로 잡히는지 (테스트 하나). → 통과. `runChecks` 테스트가 첫 커밋이 머지(그 시점 상태 `계획`)여도 실패하지 않음을 단언한다
- **검사 6의 리뷰 문서 쪽**: 충돌을 풀며 리뷰 문서를 고친 머지도 "리뷰 문서를 바꾼 커밋"으로 잡힌다. 의도에 맞는지. → 그대로 둠. 충돌을 풀며 리뷰 문서를 고친 머지도 "리뷰 문서를 바꾼 커밋"이 된다. 검사 6은 처음부터 "고쳤는가"만 보고(17 위험 1), 리뷰 문서에서 충돌이 나려면 `main`과 브랜치가 같은 리뷰 문서를 고쳐야 해서 드물다
- **`main()` 로그**: 커밋 수에 머지가 포함되면서 숫자가 지난 로그와 달라지는 것이 혼동을 주지 않는지 ("그중 머지 N개"). → 통과. 머지가 있으면 "7개 커밋, 그중 머지 1개"처럼 나와 숫자가 달라진 이유가 보인다. 머지가 없으면 지금과 같다
- **phase 17 기록**: 17 문서·17 리뷰 문서에 적은 머지 뒤 결과(`5817ee4`, `diegesis-fe-5817ee4-ba9b03`)가 `gcloud`와 같은지. → 통과. `fe-main` `5817ee4` SUCCESS, 트래픽 100% `diegesis-fe-5817ee4-ba9b03`. 17 문서·17 리뷰 문서와 같다. 지금은 이 PR의 `pr-44` 태그 리비전도 있다(머지 뒤 지운다)
